# 产品文档

> 面向产品/项目负责人。状态更新：2026-08-16

## 项目定位

MMCompare 是面向摄影/图像工作流的**本地图片对比工具**：快速并排查看多张图片、框选区域同步亮度对比、双文件夹逐张对比、EXIF/直方图辅助分析。纯本地、无网络、无账号、单窗口极简交互。

## 技术栈

| 项 | 选型 | 说明 |
|---|---|---|
| GUI | eframe/egui 0.35 (wgpu) | 原生渲染，单二进制分发 |
| 解码 | image 0.25 + jpeg-decoder | 全格式；JPEG 缩略图走解码器级降采样 |
| EXIF | nom-exif | 解析失败不阻塞加载 |
| 线程 | std::thread + mpsc | 无锁无共享，解码/扫描全部后台化 |
| 测试 | 25 个单元测试 | 状态机 + 缩略图 + 调度 + 模式互斥 |

### 待办 / 已知问题（产品视角）

| 问题 | 影响 | 建议 |
|---|---|---|
| 模式互斥静默丢弃 | 用户拖错类型无反馈 | 顶部横幅提示"文件夹模式下不支持拖入文件" |
| 无快捷键帮助 | 运行中只能靠记忆 | 按 `?` 显示帮助浮层 |
| Q 键对比与文件夹对比对功能重复 | 交互心智负担 | 统一为一种对比入口 |
| 无会话记忆 | 每次启动重新拖入 | 记住上次的路径（启动参数已支持） |
| 网格模式文件名截断无 tooltip | 长文件名看不清 | 悬停显示全名 |
| 删除无撤销 | 误删要重新打开 | 近期不做（不删磁盘文件，风险低） |
| 缩略图超 200 张无提示 | 用户疑惑 | 在视图内显示"仅预览前 200 张" |

## 路线图

### 下一阶段：视频对比（规划中）

**目标**：双视频并排对比，帧级同步播放。

| 里程碑 | 内容 | 依赖/风险 |
|---|---|---|
| M1 视频解码 | 引入视频解码（ffmpeg 系 crate），首帧提取为 cell | 依赖选型（需要验证 Windows/macOS/Linux 分发） |
| M2 视频 cell | 播放控制（播放/暂停/进度条/逐帧），与图片 cell 并存 | 与现有 cell 架构兼容（CellKind 扩展） |
| M3 视频对比对 | 双视频同步播放（帧号对齐）、Space/B 步进 | 复用现有对比对交互模型 |
| M4 性能 | 后台解码、缩略预览、内存上限（视频帧缓冲） | 大分辨率视频是主要风险 |

**架构预判**（供研发参考）：现有 cell 架构（`CellKind::Image`/`Folder`）已预留扩展点；
视频帧可复用 `ImageInfo` 的纹理链路；播放时钟需新增主线程状态机（帧推进由
`request_repaint` 驱动，与现有加载管线同模式）。

## 约束与边界

- 图片上限 8 张（`MAX_IMAGES`），由布局（≤2 行 ×4 列）决定
- 全分辨率像素常驻内存（8×50MP ≈ 1.6GB 为已知上限）
- 缩略图每文件夹上限 200 张
- 纯本地工具：不计划云同步/在线分享
